# 瓶瓶罐罐优化讨论纪要 v0.1

日期：2026-05-20
阶段：M2 已完成，进入 M3 前评审
参与角色：产品经理、UI/UX、iOS 技术/QA、项目经理

## 1. 总结结论

当前 App 已经具备“可内测”的基础，但还不能作为收费版直接上架。下一阶段不要继续扩功能，优先解决三件事：

1. 真实用户愿意连续录入产品。
2. 付费后确实解除限制，Paywall 不卖未实现权益。
3. 通知、隐私、IAP、真机适配等上架风险可控。

一句话优先级：

**先做 M3 可收费闭环，再做 M4 体验减负和真机验证，最后做 M5 上架材料。**

## 2. P0：上线前必须处理

### 2.1 Demo 数据不能进入正式版

现状：`ProductSeed` 会在空库时自动插入 3 件演示产品，正式用户首次打开会看到假数据，并且可能占用 10 件免费额度。

建议：

- 正式构建默认不插入 demo 数据。
- 如果保留演示，只能放在 Debug 或“体验示例”显式入口里。
- 空库首页要有更强引导：添加第一件正在用的产品。

用户价值：用户一打开看到的是“我的梳妆台”，不是演示 App。

风险：去掉 demo 后首屏会变空，需要同步优化空状态。

### 2.2 StoreKit 2 付费闭环必须真实可用

现状：Paywall 里“解锁 Pro”只是关闭页面，恢复购买没有实现，`ProductLimit` 也没有真实 Pro entitlement 来源。

建议：

- 接入 StoreKit 2 非消耗型 IAP。
- 商品加载使用真实 App Store Connect 商品 ID。
- 购买成功后本地状态立即解除 10 件限制。
- 启动时读取 `Transaction.currentEntitlements`。
- 监听 `Transaction.updates`。
- 实现恢复购买。
- 沙盒账号完整验证购买、取消、恢复、重装恢复。

用户价值：用户付费后马上获得明确收益，不会觉得被骗。

审核风险：Apple 对 IAP、恢复购买、误导性付费承诺非常敏感。

### 2.3 Paywall 只展示已实现权益

现状：Paywall 文案包含“高级提醒、空瓶统计、库存价值记录”等权益，但当前并未完整交付。

建议：

- M3 Paywall 主卖点收窄到“无限产品 + 本地提醒 + 本地保存 + 终身买断”。
- 明确写“终身买断 ¥28，无订阅”。
- 第 8/10、10/10、第 11 件时使用不同上下文文案。
- 不展示未实现或不确定本版本交付的权益。

用户价值：购买理由更可信。

审核风险：避免“承诺功能未交付”。

### 2.4 本地通知必须真机验证

现状：通知代码路径已经接入，但还缺真机到点触发验证，`try?` 会吞掉通知调度失败。

建议：

- 真机验证授权、拒绝、编辑日期、删除、空瓶取消提醒。
- 增加短时间测试通知模式，方便 TestFlight 内测验证。
- 通知调度失败要有日志或可诊断状态。
- 设置页增加提醒总开关和提醒规则说明。

用户价值：用户相信 App 会真的提醒，而不是只记录。

风险：通知不触发会直接伤害留存。

### 2.5 隐私和 App Store 材料要补齐

必须补：

- 隐私政策网页 URL。
- App 内隐私页与 App Store 隐私标签一致。
- App 图标。
- 6.1 和 6.7 英寸截图。
- 支持邮箱。
- 审核备注。
- IAP 随 App 一起提交审核。

注意：Apple 要求 App Store Connect 中提供隐私实践信息；iOS App 也需要隐私政策 URL。

## 3. P1：直接影响留存和转化

### 3.1 添加产品流程减负

现状：添加页是一个长 Form，照片、基础信息、日期、保质期、价格、备注全部在同一屏。

建议：

- 第一屏只保留：照片、产品名、分类、是否开封。
- 日期区改成口语化：大概什么时候开的？
- 快捷选项：刚打开、1 个月前、3 个月前、半年前、记不清。
- 保质期 Stepper 默认收到“高级设置”。
- 保存前展示结果预览：预计某天前用完。

用户价值：用户更愿意连续录入 3 件、5 件、10 件产品。

风险：录入太像“做档案”，用户会放弃。

### 3.2 首屏从焦虑警报改成今日建议

现状：Today 页首屏容易直接展示“已超过建议使用期”，第一眼偏焦虑。

建议：

- Hero 改为“今天先处理 1 件临期产品”。
- 风险说明放第二行，保持温和。
- “开启提醒”卡片不要长期压在首屏第二位，可在保存首个有到期日产品后出现。
- 统计卡从 4 列改成 2x2 或突出临期/超过建议期。

用户价值：打开 App 第一眼知道该做什么，而不是被吓到。

### 3.3 统一“过期”文案

现状：部分文案已经使用“超过建议使用期”，但列表标签仍显示“过期”。

建议：

- 面向用户统一使用“超过建议期”或“已超过建议期”。
- 法务/隐私说明中强调：日期仅基于用户记录估算，不构成安全、医疗或功效判断。

用户价值：减少焦虑，同时避免被理解成安全判断。

### 3.4 产品卡片要更有物品感

现状：所有占位缩略图都是瓶子形状，彩妆、香水、小样、工具区分度不够。

建议：

- 按分类使用不同轮廓或系统图标。
- ProductRow 展示更明确的信息：还剩 14 天 · 梳妆台。
- 详情页顶部照片放大，真实照片成为主视觉。

用户价值：女性用户管理的是自己的护肤品、彩妆、香水，不是数据库条目。

### 3.5 详情页危险操作降权

现状：删除与标记开封、空瓶、延后提醒放在同一区域。

建议：

- 删除移到更多菜单或页面底部危险区。
- “延后 7 天提醒”不要改真实到期日，应改为“7 天后再提醒我”。
- 标记空瓶后增加轻量反馈：是否回购、使用感。

用户价值：减少误删和误改日期。

## 4. P2：可放到 M4/M5

- 自定义提醒规则：15/60 天。
- 梳妆台增强：早间护肤、晚间护肤、旅行包。
- 补货清单。
- 空瓶详情和浪费金额趋势。
- 数据导出。
- iCloud 同步。
- 小组件。
- 主题图标。
- 价格 A/B：¥18、¥28、¥38。

这些都不是当前阻塞。先验证用户是否愿意录入和付费。

## 5. 技术测试补强

M3/M4 建议补测试：

- StoreKit：商品加载、购买成功、取消、恢复、退款/revoked、离线读取 entitlement。
- SwiftData：增删改、重启持久化、模型迁移。
- UserNotifications：pending request 数量、跳过过去时间、取消提醒、权限拒绝。
- ImageStore：大图压缩、HEIC、损坏图片、重复换图、删除文件、保存失败路径。
- UI 测试：添加第 1 件、第 10 件、第 11 件触发 Paywall。
- 真机测试：照片选择、锁屏通知、后台/杀进程、低电量、TestFlight 升级。
